## 1. Executive assessment

The repository contains two applications sharing a Python implementation: a skeletal animation editor currently called RigWorks 2D, and an FX preset builder. They use Pillow and PySide6, support Spine data interchange, and include their own animation evaluator, constraint solver, mesh tools, atlas packer, binary exporter, media encoders, and Windows installer.

The architecture already has useful foundations: validated FX settings, deterministic seeded generation, data-only presets, a registry of known generators, staged FX packages, atomic replacement for individual project files, and comparisons against pinned official runtimes. Preserve these foundations during cleanup. A rewrite is not justified by this review.

The principal weaknesses are boundaries between subsystems: files written outside intended folders, several output files treated as one loosely coordinated export, images changed outside undo history, source bone indices copied into another skeleton, and machine-specific development assumptions leaking into packaging and tests.

| Area | Assessment | Evidence / required next step |
| --- | --- | --- |
| Core editing and generation | Substantial functionality; additional edge cases fail | Existing tests plus 1,122 generated boundary cases; see F03–F07 |
| User data protection | Release blocker | Atlas extraction and output overwrites, PSD collisions, incomplete transactions |
| Import robustness | Needs hardening | Malformed project/preset exceptions escape expected error types; unbounded readers |
| Installation and distribution | Release blocker | Built wheel omits presets and icon; declared Qt dependency omits multimedia |
| Runtime compatibility | Promising, incompletely verified | Many parity tests pass; helper defect causes 10 false failures; native decoders need separate verification |
| Recovery and diagnostics | Insufficient for general release | Autosave enabled by default, doesnt exclude new projects |
| Performance | No production budget established | Full-frame retention and synchronous work can consume substantial memory and block UI |
| Naming and migration | Required work | Existing package, launchers, installer, formats, settings, and bridge still use previous names |
| Release governance | Missing tracked automation and release evidence | No tracked CI pipeline or license/notice files found in this checkout |

### F01 — Atlas extraction can escape the selected output directory

**Locations:** `src/spine_fx_builder/formats/atlas.py:510`, particularly page loading and construction of `target` from `r.name`; template source lookup in `templates/register.py` also deserves the same boundary review.

Atlas region names are directly joined into the destination. A region named `../escaped` was extracted to `output/../escaped.png`; the file was actually created outside the chosen output directory. Page names are also directly joined to `images_dir`, permitting reads outside that directory. Absolute, drive-qualified, UNC, alternate-stream, reserved-name, and junction/symlink cases need explicit Windows-aware handling.

**Impact:** opening an atlas can write an attacker-selected PNG path, or overwrite artwork outside the intended extraction folder, subject to the user's permissions. This is local file processing, not a proven remote or elevated exploit.

**Required change:** validate and resolve each source and destination against its allowed root; enforce containment after resolution; reject unsafe/ambiguous names; preflight duplicate targets and existing files; stage extraction before publishing outputs. Reuse the stronger containment approach already present in `models/preset.py:_safe_relative` where appropriate, with Windows-specific tests.

**Acceptance:** traversal, absolute/UNC/drive paths, alternate streams, case aliases, symlink/junction escapes, duplicate names, and existing files cause a readable error before any output mutation. Ordinary nested attachment names continue to work.

### F02 — Existing atlas pages are overwritten even with `overwrite=False`

**Locations:** `editor/document.py:1624`, `formats/atlas.py:158`, `editor/media_export.py:552`.

`export_spine_json` checks the skeleton file and one atlas filename, then `PackResult.write` saves page images unconditionally. A pre-existing `rig.png` sentinel was overwritten by exporting a new `rig.json` and `rig.atlas` with `overwrite=False`. Packed media similarly preflights a nominal atlas path rather than every generated page and scaled atlas path. Standalone pack/unpack flows also need an explicit overwrite policy.

**Required change:** compute the complete file manifest before writing, including scale suffixes, every page, atlas variants, loose images, and any naming collisions. Apply one overwrite decision to that entire manifest, before the first write.

**Acceptance:** an existing page alone blocks an export; all existing bytes remain unchanged. Cover a second page, a scaled export, `.atlas.txt`, JPEG pages, and image-copy collisions.

### F03 — Weighted attachments bind to incorrect bones after a merge or FX insertion

**Locations:** `editor/data_export.py:98`, `editor/fx_insert.py:insert_fx`.

Weighted vertices store indices into the source skeleton's bone array. Both paths copy attachments into a different bone array without translating indices by source bone name to destination bone index.

**Reproduction:** source bones `[root, arm]` and a mesh weighted to index `1`; destination already contains `[root, unrelated]`. Import Data appends `arm`, but the copied mesh still references index `1`, which now means `unrelated`. A separate isolated FX-insertion reproduction likewise bound `fx_arm` weights to `unrelated`.

**Impact:** a structurally plausible mesh silently deforms under the wrong bone and can then be saved/exported. Validate other indexed structures in the same workflows, particularly draw-order offsets, weighted paths/bounding/clipping shapes, and constraints whose ordering changes. Those additional cases have not all been reproduced.

**Required change:** introduce an explicit source-to-target bone-index map and translate every weighted attachment type. Review coordinate-space alignment when parenting FX roots and when same-named source bones are retained from the target. Perform the operation on a candidate document before committing.

**Acceptance:** source/target bone arrays with different order, extra bones, collisions, multiple skins, and weighted FX produce the intended world vertices and runtime poses after save/export. Verify name/coordinate conflicts are reported or deliberately transformed.

### F04 — Layer imports can overwrite artwork from a previous import

**Locations:** `editor/psd_import.py:178`, `:205`.

The output folder comes from `_safe(path.stem)` and layer filenames are only deduplicated within the new source's layer set. Importing two different `character.psd` files from different folders with a layer named `layer` writes both to `images/character/layer.png`. The second import overwrote a red image with blue pixels while the original slots continued referencing the same image path.

**Required change:** assign a unique persistent source identity/output namespace, preflight against all existing image outputs, and distinguish a deliberate resync of one source from a new import. Handle normalized and case-insensitive basename collisions.

**Acceptance:** two same-basename sources and sanitized-name collisions coexist without shared output filenames or changed prior pixels. Cancellation or a failed read does not leave a partial import.

### F05 — Undo snapshots omit layer-source settings and external image changes

**Locations:** `editor/document.py:128`, `editor/psd_import.py:178`, `:225`.

`_snapshot()` serializes `self.data` only. Layer import/resync also changes `project_settings['layer_sources']` and writes PNGs. After two layer imports and undoing the second, the reproduction still had **two** layer-source records. Resync changes each source's saved bounding boxes, which undo also does not restore; subsequent deltas can therefore be calculated from metadata inconsistent with the restored attachment position. Image overwrites are not restored by undo.

**Required change:** define the undo unit for a layer operation to include document changes and source metadata; use content-versioned or backed-up image assets for operations presented as undoable. If a disk change cannot be undone, make that explicit before executing it and preserve recoverable previous artwork. Avoid stale watchers after history changes.

**Acceptance:** import → undo → redo and resync → undo → resync preserve image identity, pixels, source boxes, slot positions, and watcher registrations. A failure midway restores all committed state.

### F06 — Reparenting loses the setup world pose under shear

**Locations:** `editor/document.py:389`, `:466`; `editor/affine.py:local`, `decompose`.

`bone_world_setup` constructs matrices without shear or inheritance modes, and reparenting decomposes a potentially sheared matrix into a representation documented as “without shear.” A child under a parent with `shearY=35` changed world position by about **(5.7358, 1.8085)** after reparenting; parts of its matrix also changed.

**Required change:** obtain the setup world transform from the same transform implementation used by the evaluator. Preserve shear and supported inheritance semantics during decomposition, or reject unsupported transformations before mutation. Audit split, mirror, compensation, and bake operations that share simplified affine assumptions. Their full behavior is follow-up work, not a blanket defect claim.

**Acceptance:** compare complete world matrices before/after under shear, nonuniform scale, reflection, each inheritance mode, and near-singular parents. Singular transforms produce a readable error instead of silently substituting an arbitrary inverse.

### F07 — Portal Swirl's advertised minimum collapse time fails output validation

**Locations:** `generation/casual_generators.py:200`, especially the core glow keys at normalized time `0.3` and `close`; `preset_library/portal_swirl/preset.json`, parameter `close_time`.

At the valid minimum `close_time=0.3`, the glow emits two different color keys at the same time. With the default duration of 1.4 seconds the validator reports `fx_audit_01_core_slot.color: two keys at 0.42s`.

**Required change:** explicitly handle coincident control points or adjust the control domain with a justified compatibility decision. Do not merely suppress validation. Review timestamp rounding when duration is small and controls coincide.

**Acceptance:** the exact minimum generates successfully, has unique ordered timestamps, and plays plausibly in the official runtime. Keep independent boundary cases and selected interactions in automated coverage.

### F08 — The wheel omits required application data

**Locations:** `pyproject.toml`, `resources.py:bundle_root`, `presets/library.py:default_library_dir`, `tools/build_exe.py`.

An actual wheel built from a disposable copy contained the Python package but **no** `preset_library` files and **no** `.ico` files. Resource discovery assumes a repository layout via `Path(__file__).resolve().parents[2]`; a conventional installed wheel does not provide the repository root there. The EXE build explicitly adds data, so that path is different and must be tested separately.

**Required change:** choose supported distribution channels. For wheel support, ship resources inside an importable package and locate them using package-resource APIs, including frozen handling. If source-only Python use is intentional, state and enforce that limitation instead of publishing a nonfunctional wheel.

**Acceptance:** build, install, and launch from a fresh directory outside the checkout; list all 38 presets and load the icon without environment overrides or access to repository resources. Test both CLI and GUI entry points.

### F09 — Clean installs lack multimedia features used by the application

**Locations:** `pyproject.toml:10`, `editor/reference.py:127`, `editor/video.py:78`, `editor/event_audio.py:128`.

Only `PySide6-Essentials` is declared, but MP4 export and reference video import `PySide6.QtMultimedia`. The local installed distribution's RECORD identifies `QtMultimedia.pyd` as part of **pyside6_addons**, which is present in the developer environment and masks the missing dependency. Audio catches `ImportError` and quietly cannot play; other multimedia paths import directly.

**Required change:** declare the runtime dependency needed for supported multimedia features, or make a clearly specified optional media extra with explicit capability detection and disabled unsupported UI controls. Verify the frozen payload includes the required backend libraries/plugins; their presence in a development environment is insufficient evidence.

**Acceptance:** a fresh environment installed only from declared dependencies can perform every advertised media operation, or explains unavailable operations without traceback or silent failure. Validate codecs on a clean supported Windows VM.

### F10 — Malformed projects and presets escape the user-facing error contract

**Locations:** `editor/document.py:1760`, `:1682`, `templates/spine38_ops.py:check_supported`, `models/preset.py:load_preset_file`, `models/params.py:spec_from_json`, `presets/library.py:_scan`.

A project containing a valid format/version but no `skeleton` raised raw `KeyError('skeleton')`. A preset with a string numeric bound raised raw `TypeError` rather than `PresetError`. Library discovery catches only `PresetError`, so one malformed user preset can abort discovery rather than being reported as one skipped preset. Nested JSON types are often assumed before full validation.

**Required change:** validate container types, mandatory fields, finite numbers, ranges, references, and schema versions before constructing live document/UI state. Normalize expected parser/validation failures into domain exceptions. Do not indiscriminately swallow programming errors.

**Acceptance:** fuzzed/truncated/mistyped project, variant, preset, atlas, PSD/ORA, export-settings, and `.spine` files produce readable diagnostics; the currently open document and valid library entries survive. Include invalid UTF-8, `NaN`/infinity, excessive nesting, wrong top-level types, and missing keys.

### F11 — Filesystem failures do not reliably become actionable UI errors

**Locations:** `editor/main_window.py:217`, `:662`; `editor/export_dialog.py:_export_clicked`; `ui/main_window.py:export_for_engine`; `ui/worker.py`.

The editor's general `_guard` catches `EditorError`, while save/write/replace/copy operations can raise `OSError` subclasses directly. The export dialog also catches only `EditorError`. FX engine export restores the cursor in `finally` but does not convert arbitrary filesystem failures into a result. The worker does catch unexpected failures, but prints tracebacks to a console that may not exist in the windowed executable.

**Required change:** add operation-boundary error translation and persistent rotating diagnostic logs. Explain which target failed, whether the previous file survived, and how to retry. Keep dirty state and original project bytes intact on failure. Do not treat a failed side-effect export as failure to save an already-saved project.

**Acceptance:** injected disk-full, read-only, sharing-violation, missing-directory, and unplugged-drive errors do not escape Qt callbacks or lose edits. Export progress and buttons reset correctly, and logs provide a supportable error record.

### F12 — Cleanup removes duration-defining terminal keys

**Locations:** `editor/data_export.py:36`, `:54`; related behavior in `editor/bake.py:simplify_keys`.

The last repeated value key is removed even when its timestamp establishes the animation's duration. A one-second timeline `[{value: 0}, {time: 1, value: 0}]` became `[{value: 0}]`. Spine runtime duration is derived from timeline endpoints, so an optimization can change loop timing, mixes, and completion callbacks while leaving sampled values unchanged.

**Required change:** preserve the animation's original duration across cleanup/simplify, or make any deliberate duration change an explicit separate operation. Merely comparing poses at a few timestamps misses this semantic change.

**Acceptance:** constant-tail and constant-only animations retain duration and loop/completion timing in JSON and binary, with events and crossfades included in comparisons.

### F13 — Multi-file editor exports are not atomic as a package

**Locations:** `editor/document.py:1624`, `formats/atlas.py:158`, `editor/media_export.py:552`, `editor/unity_bridge.py:export_to_unity`.

The skeleton is replaced before page images/atlas/loose images finish writing. An error later leaves a new skeleton with old or incomplete supporting resources. Individual media files are also saved directly to their final paths. The staged `packaging/package.py` and `packaging/engine_export.py` workflows provide a better starting point, although their public error/result contracts also need consistency.

**Required change:** stage all outputs in the destination filesystem, validate the complete manifest, and commit with a recoverable package protocol. A series of renames is not inherently one atomic transaction: define rollback or a versioned-directory strategy. Use unique temporary files, a concurrency policy for two windows exporting/saving the same target, and cleanup of failed work. Do not remove unowned files or Unity `.meta` assets during cleanup.

**Acceptance:** inject failure after each write and replacement; previously valid exports remain usable, incomplete output is clearly marked, retry is safe, and no existing unrelated file is touched. Test overwrite, new export, changed page count, and Unity auto-export.

### F14 — Uninstall trusts arbitrary paths from `install.json`

**Location:** `installer/rigworks_setup.py:181`.

Manifest `files` entries are joined directly to the installation path, and `shortcuts` entries are unlinked as absolute paths. A mocked-deletion reproduction recorded deletion requests for `install/../outside.txt` and an unrelated shortcut. No real outside file was deleted during the audit. Manifest-provided registry and Start-menu values are also trusted.

**Impact qualification:** this does not establish privilege escalation; a user-writable manifest is processed with the current user's permissions. It does violate the installer's promise to remove exactly its own files and is a destructive-boundary reliability problem.

**Required change:** validate manifest schema and installation identity; allowlist installed basenames and known shortcut locations/names; resolve and enforce containment; reject unexpected registry keys. Replace or strictly constrain the shell-built self-deletion command, including paths containing shell metacharacters or expansion syntax.

**Acceptance:** tampered traversal/absolute paths, unexpected shortcuts/registry keys, missing or malformed manifests, and partial installations are rejected without unrelated deletion. Removal of owned files still succeeds and user projects/templates/settings remain intact.

### F15 — Installation failure can strand or partially upgrade an installation

**Location:** `installer/rigworks_setup.py:124`.

The installer copies program files, creates shortcuts, and registers uninstall information before writing `install.json`. A shortcut or registry failure before the manifest write can leave a nonempty installation folder with no manifest. The next install rejects a nonempty folder without a manifest. An upgrade similarly overwrites the program before confirming later steps, with no observed rollback.

**Required change:** preflight payload completeness and access; stage payloads; record ownership/recovery state before external side effects; roll back or resume interrupted installation. Validate existing manifests, do not accept any unrelated `install.json` as proof of ownership, and test upgrade while the program is running.

**Acceptance:** failure at every install step leaves either a working previous version or a repairable new installation. Reinstall/repair does not require users to manually delete folders. Test custom/Unicode/long paths, shortcuts, per-user registry, cancellation, upgrade, uninstall, and reboot/interruption scenarios in a disposable VM.

### F16 — Save As breaks relative audio paths

**Locations:** `editor/document.py:1738`, `editor/event_audio.py:21`, `:34`.

`images_dir` is rebased when saving; project settings are serialized unchanged. Saving a project from `old/p.rig2d` to `new/p.rig2d` with audio setting `audio` changed resolution from `old/audio` to `new/audio`, and a previously resolvable sound became missing.

**Required change:** centralize project asset references and rebase every relative reference on Save As, including audio, reference footage, imported-layer sources, and future resource settings according to their intended portability policy. Define Save As versus “collect/copy project assets” behavior explicitly.

**Acceptance:** same-drive, cross-drive, moved-project, and network-path Save As preserve references or deliberately collect resources with clear reporting. Test after reopening, not just in the existing session.

### F17 — Importers need resource bounds before allocating or recursing

**Locations:** `formats/spine_project/__init__.py:35`, `formats/spine_project/reader.py`, `editor/psd_import.py`, `formats/atlas.py:510`, `editor/document.py:1760`.

Raw-deflate `.spine` data is decompressed with no output cap. Reader varints, list/object counts, and graph depth do not have a consistent budget. PSD dimensions/counts and atlas original dimensions can drive allocations; ORA uses full `ZipFile.read` calls. The template analyzer has a 32 MB JSON bound and preset PNGs an 8 MB compressed-size limit, but those are not a common bounded-import policy and do not bound decoded memory everywhere.

**Required change:** enforce compressed/decoded byte, image pixel, element count, vertex/influence, frame, nesting, and elapsed-time budgets at the reader boundary. Validate integer ranges and truncated primitive reads. Handle decompression completion/truncation explicitly. Consider an isolated import process for native decoders/untrusted large files.

**Acceptance:** small adversarial fixtures cannot allocate unbounded memory or freeze the UI; cancellation and readable rejection work. Test limits with controlled fixtures rather than actually exhausting the user's workstation.

### F18 — Media work needs streaming, cancellation, and memory budgets

**Locations:** `editor/media_export.py:104`, `:251`, `:552`; `editor/video.py:render_animation`, `write_mp4`; `editor/reference.py:21`; `ui/preset_browser.py:render_thumbnails`; export dialog callbacks.

Export retains frame lists, often both QImage and Pillow copies, and some formats build whole output byte sequences in memory. Reference footage can retain up to 3,000 scaled frames with a side up to 1,280 pixels: 1,280 × 720 × 4 × 3,000 alone is about **10.3 GiB**, before object/decoder overhead. A 120-frame 4096 × 4096 RGBA export alone is **7.5 GiB** per uncompressed full set. Per-side size checks are not a total-memory budget.

Several expensive flows run synchronously from dialog callbacks. Thumbnail generation is eager and scales with user-library size. The presence of one FX worker does not make the entire editor responsive.

**Required change:** estimate cost before work; stream video/frame sequences; bound caches by bytes; use on-demand reference decoding or a limited preview cache; support cancellable jobs with immutable inputs and explicit cleanup. Separate QPixmap/UI-thread requirements from worker-safe processing. Establish performance targets through measurement.

**Acceptance:** a documented representative large project/export remains within its memory budget; UI cancellation responds promptly; repeated imports/exports do not grow retained memory; timeouts do not report success with partial files. Benchmark cold start, large library load, scrub/playback, save, undo, atlas packing, and media export.

### F19 — Large mesh exports can be silently cropped

**Location:** `preview/qt_renderer.py:96`.

`_draw_mesh` caps its intermediate width and height at 4096 while retaining the original left/top and vertex positions. Media export accepts larger output dimensions. A mesh spanning more than the intermediate cap can therefore lose its right/bottom area even when the enclosing output is valid. This is code-confirmed; no exhaustive pixel-golden reproduction was performed.

**Required change:** tile rendering, allocate against a validated budget, or reject unsupported sizes with an explicit message before export. Do not silently clip the layer.

**Acceptance:** a mesh spanning >4096 pixels renders all expected corners at an allowed output size, including clipping/blend/alpha, or the UI rejects the size consistently. Compare with equivalent region geometry.

### F20 — Recovery coverage is insufficient

**Locations:** `editor/settings_dialog.py:19`, `editor/main_window.py:987`, `editor/app.py:main`, `editor/document.py:save_copy`.

Autosave defaults to zero/off, returns immediately for a new unsaved project, and writes a single sibling `.autosave` copy for named projects. No recovery discovery/prompt was found in the inspected startup/open flow. Atomic individual file replacement is useful, but is not a recovery system or protection against loss of a never-saved session. The fixed temporary filename also needs a two-writer policy.

**Required change:** provide a recoverable session location for unsaved documents; define default autosave and retention; detect recovery candidates on startup/open; preserve successful previous versions; handle read-only source folders and cleanup after deliberate save/discard.

**Acceptance:** terminate the app during editing, autosave, and save; the next launch offers the correct recoverable state without overwriting a newer project. Verify new documents, multiple skeletons, two windows, network/removable media, and migration from `.rig2d`.

### F21 — Ten binary parity failures come from a shared test adapter

**Locations:** `tests/runtime/check_spine38.js:75`; locally pinned official runtime `tests/runtime/vendor/v40/spine-core-4.0.js:7106`.

The helper passes a Uint8Array view over a Node Buffer using its `byteOffset`. The pinned runtime's `BinaryInput` constructs `new DataView(data.buffer)` and does not honor that offset. Small files can come from Node's pooled backing buffer. The failed 387-byte `hero.skel` had offset **8**; the runtime read unrelated bytes before the real header. Larger files can accidentally avoid the problem.

An in-memory replacement of `new Uint8Array(bytes.buffer, bytes.byteOffset, bytes.length)` with **`Uint8Array.from(bytes)`** gave the runtime an independent zero-offset buffer. All ten previously failing cases passed, using the unchanged product exporter and unchanged runtime. Do not change binary serialization to accommodate a misaligned test input.

The ten cases were:

- `tests/test_binary.py::test_synthetic_rig_loads_identically_from_binary`;
- all six `tests/test_constraints.py::test_constraint_modes_match_runtime` variants;
- `tests/test_editor.py::test_binary_export_plays_like_json`;
- `tests/test_editor.py::test_export_with_packed_atlas_loads_through_the_runtime_atlas`;
- `tests/test_skins.py::test_skins_play_like_the_runtime`.

**Required change:** fix the adapter in a later implementation change; add a focused test for nonzero-offset/pooled buffers and multiple file sizes; keep the pinned runtime unmodified.

**Acceptance:** all ten pass without the audit shim, and the full supported suite runs on CI. This is verification-infrastructure work, not evidence that all binary edge cases are now certified.

### F22 — Important compatibility tests are not portable, and decoder failures remain unresolved

**Locations:** `tests/test_spine_project.py:27`, `tests/test_export_suite.py:273`, `tests/test_reference.py:55`, `docs/compatibility.md`, `tools/fetch_spine_runtime.py`.

The completed run skipped **23 `.spine` cases** requiring examples or user projects at hard-coded machine paths. Five native-decoding cases were deselected after two process terminations. The compatibility document's green automated claims need qualification against the reproducible state, particularly the broken helper and missing project fixtures. User-specific fixture paths should be replaced; no conclusion about rights to those source files is made here.

**Required change:** create a portable licensed/synthetic fixture corpus or an explicit restricted fixture provisioning mechanism; separate core, official-runtime, native-media, and manual-editor test tiers; make required CI fixture absence fail rather than silently reduce coverage. Keep individual decoder tests in subprocesses so native crashes can be reported as test failures with diagnostics. Confirm behavior in the supported runtime and packaged app before assigning decoder root cause.

**Acceptance:** documented commands reproduce the required tier on a clean machine; every skip has a policy and owner; native crashes preserve a diagnostic record; Spine/Unity manual checks name exact versions, date, artifacts, and results.

### F23 — Generation completion can modify a different session than the job used

**Locations:** `ui/main_window.py:generate`, `:265`, `:397`; `ui/worker.py`.

The job captures a preset/settings pair, but completion reads and changes `self.session`, which is the currently selected session. Preset switching is not visibly frozen by `generate`; only busy/generate controls are managed. Switching presets before completion can therefore advance/report the wrong instance name. Close waits at most ten seconds for the global pool, with no explicit per-job cancellation or completion policy. This is a code-confirmed race risk; a timed end-to-end reproduction was not performed.

**Required change:** associate a job ID and initiating session ID with each result; update only that session; discard stale preview callbacks; specify cancel/close behavior. Avoid blocking the UI waiting on unrelated global thread-pool tasks.

**Acceptance:** switch presets, change settings, reload templates, close/reopen the builder, or open another builder during a delayed job; the correct result and session update once, without stale callbacks or indefinite shutdown.

### F24 — Release identity and controls are incomplete

**Locations:** `pyproject.toml:7`, `src/spine_fx_builder/__init__.py:3`, `resources.py:8`, `installer/rigworks_setup.py:28`, `packaging/package.py`.

Python metadata and generation reports identify **0.1.0**, while application/installer versions identify **0.15.1**. Multiple manually synchronized constants create drift. The wheel's description presents only the FX companion and its old target. README says 37 presets and includes milestone/future-work text inconsistent with the 38 checked-in presets and current features. Several module descriptions describe earlier scope, for example region-only rendering and no audio playback despite current implementations.

No tracked CI configuration, lockfile, root license, or third-party notice file was found in this checkout. This establishes missing release artifacts, not a conclusion about legal permission. The README states unsigned Windows distribution. Build dependencies are documented partly in a script docstring rather than a complete reproducible build profile.

**Required change:** establish one version source and generated metadata, a supported-platform/runtime matrix, reproducible dependency/build inputs, CI gates, artifact hashes/provenance, release notes, distribution signing policy, ownership for security/bug reports, and a reviewed dependency/art/fixture notice inventory. Verify applicable distribution terms with the appropriate owner before release; this audit does not give a legal opinion.

**Acceptance:** app About/version, CLI, wheel, installer, logs, and generated reports agree; clean build is repeatable; required test tiers run before release; installer/artifact identity is auditable; current docs describe tested capabilities and actual limitations.
